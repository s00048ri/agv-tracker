# `sources/` — Source Registry and Coverage Matrix

This directory is the **single source of truth** for every external source the AGV
Tracker pipeline relies on. See CLAUDE.md §5 for the full spec of the three-layer
model and §5.4 for the coverage-matrix deliverable.

## Files

| File | Purpose | Human-editable? |
|---|---|---|
| `registry.yml` | Canonical list of all sources with role, coverage, and metadata | Yes |
| `coverage_matrix.md` | Auto-generated cross-tab of `entity_type × geographic_scope` against the registry | No — regenerated by script |
| `README.md` | This file | Yes |

## The three-layer model (CLAUDE.md §5.1)

Every source entry has a `role`:

- **`discovery`** — helps find candidate AGVs (e.g. OECD.AI Policy Navigator, IAPP
  tracker). Seeds monthly diff PRs. **Never** acceptable as `primary_reference_url`
  in `data/agv.csv` and **never** cited in `agv_evidence.csv` as authoritative.
- **`verification`** — first-party authoritative source for an AGV's existence and
  classification (e.g. the Council of Europe CAI page for the CoE Framework
  Convention on AI). **Must** be the `primary_reference_url` and **must** be the
  cited source for any field with a `confidence_*` column.
- **`background`** — conceptual / theoretical literature (e.g. Stanford AI Index,
  Hannan & Freeman 1989). Cited in `src/methodology.md` and the companion SSRN
  paper. **Never** populated into `data/*.csv` fields.

A source may legitimately serve more than one role, but each role requires a
**separate entry** with a distinct `id` (e.g. `oecd_ai_navigator` vs.
`oecd_ai_official`). This keeps role semantics crisp and makes the coverage
matrix honest about whether an `entity_type` has both a discovery surface and a
verification surface.

## `registry.yml` entry schema

```yaml
- id: <snake_case_unique_id>         # required
  name: <human readable>             # required
  url: <https://...>                 # required
  role: discovery | verification | background   # required
  entity_types_covered:              # required for discovery/verification; [] for background
    - <AGVO §3.3 D1 value>
  fetcher_module: <python.dotted.path | null>   # null when no fetcher exists yet
  fetch_strategy: http_static | http_with_playwright_fallback | manual
  update_frequency: monthly | quarterly | annual | ad_hoc
  last_verified_alive: YYYY-MM-DD    # last day the URL was manually confirmed reachable
  notes: <freeform>                  # optional
```

## How to add a new source

1. Pick the right `role`. If unsure, default to `discovery` — it's the role with
   the weakest downstream obligations.
2. Add a YAML entry to `registry.yml` with a unique `id`. Keep the id stable
   forever; fetcher modules and evidence rows may reference it.
3. Set `last_verified_alive` to today's date (you just visited the URL, right?).
4. Regenerate the coverage matrix:
   ```bash
   python3 scripts/generate_coverage_matrix.py
   ```
5. Commit both `registry.yml` and `coverage_matrix.md` in the same commit. The
   matrix is committed to Git so its evolution is visible in history.

## How to add or change a verification source for an `entity_type`

Verification sources are load-bearing: they are what gets cited in
`agv_evidence.csv` and what appears as `primary_reference_url` in `agv.csv`. Be
conservative.

- Adding a verification source: ensure it is first-party (official site, founding
  document, host-government page) — not a registry that merely lists the venue.
- Retiring a verification source: existing `agv_evidence.csv` rows pointing at it
  are not automatically invalidated. Record the change in `CHANGELOG.md` and
  leave the evidence history intact.

## Release gate (§5.4)

**No release is allowed if any cell in the coverage matrix has AGV count > 0 but
lacks a designated verification source.** The generator prints a `FAIL` / `PASS`
verdict in `coverage_matrix.md` under the "Release gate" heading; CI should
parse that section and block the `v*.*.0` tag if either check fails.

The matrix also surfaces:

- Every `entity_type` from AGVO §3.3 Dimension 1 with no verification source
  anywhere in the registry (hard fail).
- `entity_type` values present in `data/agv.csv` but not defined in AGVO (soft
  warning — likely a typo or an ontology extension that never landed).

## Regeneration

```bash
python3 scripts/generate_coverage_matrix.py
```

The script has two inputs (`registry.yml`, `data/agv.csv`) and one output
(`coverage_matrix.md`). It reads no network and requires only `pyyaml` at
runtime. It is safe to run as often as you like; it is deterministic except for
the `Generated:` timestamp line.
